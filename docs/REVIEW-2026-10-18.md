# 项目审查与调整方案（2026-10-18）

初版只交付审查与方案。随后用户确认取消自动回滚，改为失败后由卸载功能清理并重装，同时要求安装完成后不留下组件缓存或旧文件残留；这些安装生命周期调整已完成。其余安全项仍按下表状态处理。

## 复审结论

原方案的安全修复方向成立，但范围偏大。保留会直接导致用户文件丢失、错误恢复到已提交安装或并发破坏的项；删除没有独立收益的兼容框架和版本管理链。

| 方案项 | 结论 | 最小做法 |
|---|---|---|
| 组件目录整目录删除 | 已完成 | 只删除安装记录里的受管文件；未知文件保留，空目录随后清理 |
| 自动回滚 | 删除 | 安装前写 `complete=false` 的完整清理清单；失败不回写旧文件，用户卸载后重装 |
| 卸载前哈希预检 | 暂缓 | 先检查全部受管文件；修改过或无法确认的文件保留并报告，再删除其余文件 |
| 单实例锁 | 已完成 | 删除 `--diagnose` 绕过，所有入口共用同一把锁 |
| 原子替换与提交边界 | 待处理 | 用一个 Windows 替换调用保护记录和配置；安装记录写成功后，清理失败只报告 |
| PE 越界与算术溢出 | 保留 | 条件成立后再计算偏移，所有切片先验证范围；补一个畸形或截断输入回归测试 |
| 损坏安装记录 | 已完成 | 区分“记录不存在”和“记录损坏”；损坏时停止，不能当成首次安装 |
| 兼容版本白名单 | 删除 | 稳定版签名、固定 extra SHA-256 和主包 INT4 清单已经会安全失败，不再维护第二套人工兼容表 |
| 资源包内逐文件哈希 | 删除 | 已经由 extra ZIP 的 SHA-256 覆盖；只需保留跨包兼容所需的 INT4 清单校验 |
| 310.9.16 安装选项 | 暂缓 | 当前稳定版不支持该模型；等上游稳定 Release 引入后，再按实际包结构增加一个选择值 |
| 命令行模型参数、记录迁移、模型管理框架 | 删除 | 未来若恢复功能，优先复用现有 `extras_version`，并只写一个模型选择 INI 键 |
| 全套 NTFS 路径测试矩阵 | 拆成独立加固 | 本轮只覆盖实际改动涉及的重解析点、越界和记录路径；ADS、保留设备名等另列安全任务 |

当前安装界面还有一个与原目标冲突的设置：普通用户可以直接编辑安装器仓库、固定资源地址和 SHA-256，并能导入任意本地 ZIP。固定方案应只展示自动更新和数据目录；离线 ZIP 仍可作为维护入口放在 `--advanced` 或命令行，避免正常用户拼出不兼容组合。

`previous-record.json` 和旧事务文件不再写入；启动清理会删除历史残留。安装失败由 `record.json` 的 `complete=false` 表示，记录同时包含旧版和新版受管路径，供卸载清理。

安装成功、卸载和启动时会清理组件下载缓存、解压 staging、旧备份、旧事务文件和安装器更新残留。数据目录只保留安装记录、设置和签名更新元数据。

| 优先级 | 代码证据与问题 | 影响 | 建议方案 |

| P1 | `src/install.rs:96` 创建的事务没有恢复副本，`:652` 的恢复操作删除目标；事务还包含安装前已存在的 INI | 原实现不能真正恢复到安装前状态 | 已取消自动回滚；先写未完成记录，失败后提示用户卸载重装 |
| P1 | `src/install.rs:578` 卸载时只按路径删除，没有核对记录中的 SHA-256 | 安装后被替换或修改的文件可能误删 | 删除前完整预检；保留修改过的文件并明确报告，避免删到一半才发现冲突 |
| P1 | `src/main.rs:19` 诊断绕过单实例锁，但 `:102` 调用会恢复事务、清空 staging 的函数 | 同时运行诊断和安装可能破坏正在进行的安装 | 删除诊断绕过；所有会恢复或清理文件的入口均获得同一实例锁 |
| P1 | `src/util.rs:51` 的 `write_atomic` 和安装复制函数先删旧文件再重命名 | 进程中断、锁定或重命名失败会留下丢失的配置/记录/文件 | 使用 Windows 原子替换 API；失败保留旧文件；明确安装记录为提交点，提交后清理日志失败不得触发撤销已提交安装 |
| P2 | `src/pe.rs:89` 使用立即求值的 `then_some` 计算 RVA 偏移；`:62` 直接用文件偏移切片 | 某些 RVA 会触发调试算术溢出；畸形 PE 可越界崩溃，影响游戏扫描 | 条件成立后再计算地址，检查原始数据范围并用 `get` 访问；补低 RVA、多节和越界导入名测试 |
| P2 | `src/install.rs:53` 将损坏的记录读成“没有记录”；`:477` 在检查大小写冲突前用小写键覆盖重复计划项 | 丢失所有权信息；大小写冲突检查失效 | 区分记录不存在和记录损坏；验证记录所属游戏及相对路径；重复路径在进入映射前拒绝 |
| P2 | `scripts/publish-catalog.ps1:56` 自动签署最新稳定上游；`src/assets.rs:208` 只比较 INT4 哈希 | 签名证明来源，不能证明主包与模型、运行时、XeFG 组合兼容 | 保留现有的 SHA-256 与 INT4 兼容检查，不匹配时停止；不新增维护者人工兼容清单或重复的逐文件校验 |

Windows 专项路径加固（NTFS 数据流、设备名、尾随点和空格）单列安全任务。本轮只测试改动会经过的目录联接/重解析点和记录路径。

## 文案与版本选择

统一显示文案为：

**OptiScaler NR + Mochizuki 后端 + Intel XeFG**

同步范围：根 README 和 `src/model.rs` 的 `FIXED_PROFILE`；界面从该常量读取。第三方来源说明中的署名仍保留。

当前安装页不增加模型来源选择框。这个选择依赖主包的 `MochizukiNetworkModel` 和支持 `dlssnr-small.bin` 的完整运行库；现有稳定包缺少两者，单独提供 DLL 或模型文件不会切换实际模型。

文案只需要改根 README 和 `FIXED_PROFILE` 常量，界面及维护入口都从该常量读取。历史 Release 说明保持原文，不能改写成当前方案。

未来稳定主包支持双模型后，最小功能只包括：一个安装时选择值、对应的已提取模型文件、一个 `MochizukiNetworkModel` 写入和一条安装记录字段。旧记录缺失该字段时按 310.8.0 解释；修复和更新沿用已记录值。无需命令行参数、兼容白名单或通用模型管理框架。
