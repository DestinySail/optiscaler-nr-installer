# Domain docs

This repository uses a single-context layout:
- GLOSSARY.md at the repository root.
- Architecture decision records under docs/adr/.

Before exploring code, read the glossary if present and ADRs relevant
to the task. If absent, proceed silently without creating placeholders.
The domain-modeling skill creates these documents when terms or
decisions are resolved.

Use glossary terms consistently. Reconsider unfamiliar terminology
or note genuine gaps for domain-modeling.
Explicitly flag any proposal that contradicts an existing ADR.
